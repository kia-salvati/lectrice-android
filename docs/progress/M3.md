# M3 · Real playback (2026-10-25/26, Opus + Fable)

Files 05, 06, 08, 09, 15, 16, 17 (notifications, media). Code in `core:playback`, `core:data` (engine), the reader
ViewModel, and Fable's reader UI (`M2-ui-B.md`).

## What was built

- **`Media3PlaybackController`** (implements `PlaybackController`; process-wide, on the main looper): one ExoPlayer whose
  playlist is a **window of sentences** (`PlaylistWindow`: 50 behind, 150 ahead, +200 when fewer than 50 remain ahead;
  appends and drops are batched so the timeline changes rarely). Per-item metadata per file 09 §3.3 (title = the sentence
  cut to 120 chars, artist = "Ch. 7 · Book"; with the setting off: section title + book; rebuilt in place when the setting
  changes). Status per file 05 §3.8 (Preparing right after play/jump, Catching up mid-play, Finished, Voice not installed,
  Voice unavailable). Strict previous/next (`setMaxSeekToPreviousPositionMs(0)`). Speed via `PlaybackParameters` (Sonic,
  pitch kept). Voice change: `stop_read_ahead` + rebuild around the current sentence. Read code change: new playback order
  from the core, rebuild. Positions through `PositionSaver` (5 s while playing, at once on pause/jump/book change/
  background). Errors (file 09 §3.5): synthesis failure retried once, then skipped with a snackbar, 3 in a row → Voice
  unavailable; `ModelMissing` → Voice not installed; `SentenceNotFound` → order rebuilt; `VoiceUnknown` → default voice.
  Speech stats polled every 30 s while playing (`rtf` in `PlaybackState`, feeds the slow-phone tip and the export estimate).
- **One generation queue** (spike follow-up): ExoPlayer's buffer is small (5–15 s), so the player only preloads the next
  few sentences; everything further ahead is the core's read-ahead on the same speech worker (same-key jobs merge).
- **`SentenceDataSource`**: blocks on ExoPlayer's loader thread on `speak_sentence` (loads the engine first through
  `EngineHost`), WAV bytes back, `ready_ahead_ms` kept for the slider's buffered part.
- **`ReadAheadController` + `ReadAheadGovernor`** (file 08 §3.3, pure decision table, JVM-tested): Full / Reduced (2 min)
  / Off from: no book, sleep timer fired, low memory while stopped, thermal SEVERE/CRITICAL episodes (2 cool minutes to
  end), paused ≥ 60 s, battery saver or ≤ 15 % not charging (Off while paused, Reduced while playing). Off sends
  `stop_read_ahead` once and `plan_ahead = false` on every `speak_sentence`. `DeviceConditions` feeds battery and thermal
  status.
- **`EngineHost`** (`core:data`): loads the active model lazily (first play, prepare or export), one engine at a time,
  unloads after 5 idle minutes or on `onTrimMemory(BACKGROUND)` while not playing; reports `VoiceState` (not installed /
  downloading / installed / failed) for the L5 banner, the pill and R9. **Threads per phone class** (`DeviceProfile`):
  every core with ≥ half the fastest core's capacity, 2–8 → 4 on the S10+, 8 on the S26 Ultra; Settings can override
  (`threadsOverride`, no UI yet).
- **`PlaybackService`** (`MediaSessionService`, type `mediaPlayback`): lock screen, notification, Now Bar, Bluetooth and
  headset buttons; the seek-in-item command removed; media resumption after process death rebuilds the last book at its
  saved place. Started by binding a `MediaController` on the first play, so Media3 promotes it to the foreground while
  playing (Samsung throttles background work otherwise, spike S7). ExoPlayer: speech audio attributes with audio focus,
  becoming-noisy pause, `WAKE_MODE_LOCAL`.
- **Sleep timer** (file 15): minutes count down only while playing; at 0 the current sentence finishes
  (`pauseAtEndOfMediaItems`) with a 3 s fade; End of chapter pauses after the last sentence before the next chapter-level
  entry and follows jumps; firing turns the governor Off at once.
- **Voices** (file 16): per-book voice and speed (`SettingsStore.bookListening`), defaults in Settings, samples through
  `CoreVoiceSamplePlayer` (core `speak_voice_sample`, cached on disk; the book pauses and resumes after).
- **Listen view over the lock screen** (file 06 §3.6): the reader calls back when the Listen view opens/closes; the
  activity sets `setShowWhenLocked(open && setting)`.
- **Notification permission** (file 17 §3.2): asked once ever, before the first play or the first download (the R10
  pre-sheet is not built: the system dialog only; listed as a gap).

## FFI (Android repo)

`speak_sentence` takes `plan_ahead`; `stop_read_ahead`, `stop_all_read_ahead`, `set_read_ahead_minutes`,
`speak_voice_sample`, `speech_stats`, `unload_engine` (new `EngineStatus::Unloaded`); `EngineConfig::Kokoro` gains
`engine_id` (our bundles report their own id through `BundleSpeechEngine`).

## Where another engine plugs in

- Kotlin: `core:data/ModelCatalog.kt` (one more `ModelSpec`, or a flag on an existing one) and `EngineFactory.config()`
  (the only place that builds an `EngineConfig`).
- Rust: `rust/lectrice-ffi/src/composition.rs` `load_engine()` is the only factory; add an `EngineConfig` variant
  and a branch that returns any `Arc<dyn SpeechEngine>`; give it its own engine id like
  `BundleSpeechEngine` does, so cached clips never mix. Nothing in playback, read-ahead, export or prepare changes.
- `EngineHost` keeps "one engine at a time".

## Checked on the Galaxy S26 Ultra (2026-10-26, debug APK, phone locked, over adb)

The phone stayed locked (PIN), so the UI itself was not seen; everything below ran behind the lock screen through
debug-only intent extras (`--es lectrice.play <docId>`, `--es lectrice.export <docId> --ei lectrice.speed 150`).

- Import of an invented 17-page book through "Open with" (`ACTION_VIEW` content URI): 90 ms, 709 sentences, 30 TOC entries.
- Play: the Fast model loaded in 0.6–1.3 s with 8 threads and the engine id `kokoro-v1.0-lectrice-fast-v1`; first
  sentence made, read-ahead planned ~600 s; sustained RTF 0.48 after 30 s (speech stats). Media session PLAYING with the
  sentence as the title; the playback service went to the foreground.
- **Bug found and fixed:** the lock screen / headset buttons did nothing (the session offered only `SET_RATING`): the
  `onConnect` override dropped the play/pause/next commands. Now a `ForwardingPlayer` removes only "seek in item".
  After the fix: media key pause → PAUSED, next/previous step exactly one sentence (ids 39 → 40 → 39 → 38).
- Position saved while playing and on pause; reopening resumed at the saved sentence.
