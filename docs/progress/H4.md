## What was built

- **FFI (C49)** `rust/lectrice-ffi/src/helper.rs`, `api.rs`, `composition.rs`: pairing (`helper_pair` → `PairOutcome`:
  paired / wrong code / no code / not local / incompatible / unreachable), `helper_configure` (identity key + the pinned
  computer + last addresses), start/stop/status/retry/addresses, `HelperListener.on_state`, Prepare through the helper,
  the deferred engine (C46: the phone's model loads only when the phone has to speak itself). Sockets: `socket2` makes an
  unconnected socket, Kotlin binds a dup of its fd to the Wi-Fi `Network` (`Network.bindSocket`), so no `unsafe` and
  mobile data or a VPN never carries the link.
- **`core:link` (C50)**: `ComputerHelperHub` (the repository the screens use; runs the link while the governor is Full or
  Reduced or a Prepare range is on the computer), `ComputerFinder` (NsdManager, `_lectrice._tcp`, by `id` TXT only),
  `WifiNetwork` (Wi-Fi/Ethernet callback + binder), `IdentityKeyStore` (X25519 key wrapped with a non-exportable
  Keystore AES-GCM key), `LinkFiles` / `PeerList` (`peers.json`, ≤ 4 computers), `HelperLinkState` (pure, JVM-tested).
- **Governor + Prepare (C51)**: `ReadAheadGovernor.helperRuns` (Full/Reduced fill, Off stops), the "lost" read-ahead
  length from the core (`helper_lost_read_ahead_minutes`: 30 min on the S10+ class), preload on Lost; `PrepareCenter`
  runs a range on the computer while it is connected (no charger needed).
- **UI (C52, Fable)**: Settings row + H1/H9 page, H6 rationale + denied card, pairing pages H2–H5, the pill's computer
  mark, the player sheet's helper line with Fix, "Prepare on *name*" with the bolt icon, the `ComputerLost` snackbar.

## Fixes made in this pass (found on the S10+)

1. **Prepare on the computer: two books took turns.** The computer holds one Prepare range; with two requests the 1 s
   service tick started each in turn, every start replacing the other and cancelling 12 queued items (one book went
   500 → 504 sentences in 48 s). `PrepareCenter.tick` now starts at most one range on the computer, keeps a book that
   reached Ready as Ready, and treats a start that is already complete as Ready.
2. **`HelperBusy` during Prepare** (security §9.6.1): a range the computer stopped short of its end (refused items) is
   sent again after 30 s instead of on the next tick.
3. **Reconnect after the desktop came back took ~60 s.** Android's NSD doesn't report again a computer that vanished
   without a goodbye (crash, sleep), so the fresh sighting that triggers `retry_now` never came and the link waited for
   the 60 s retry. While Lost, the hub now browses again every 10 s: measured 20 s with a 20 s period, ≤ 12 s expected
   with 10 s (not re-measured after the last change).
4. **The link stayed open after a Prepare range on the computer ended** while nobody listened (`keepAlive` was read only
   when the governor changed). The hub re-decides when Prepare's "runs on the computer" flips.
5. **"Last seen" was the moment the session started** (the row said "Last seen 15 min ago" right after a 15-min session).
   It is now also stamped when the computer stops making audio.
6. `PdfTooComplex` (1010) gets its own import text; `RequestForbidden` (1009) is web-only and falls back to the
   generic text.

Fable's deviations reviewed and kept: generic "update the older one" (the core doesn't say which side is older); model
missing without the model's name/size (the state doesn't carry it; see open items); the ⋯ menu as a Compose `Popup`;
"Last seen" computed at draw; code boxes cleared on every error; the live switch on H5.

## Open items

1. **Core (lectrice-app), first sentence races load the phone's engine.** (a) At play the link is still Connecting for
   ~100 ms, so the local read-ahead plans and starts one item before `pause_for_helper` cancels the rest (engine loaded,
   2.2 s). (b) A miss that the computer answers after the 1.5 s grace (1.95–2.06 s measured: cold desktop engine, or a
   voice change while an item was being made) also loads the engine and makes the sentence twice. Suggestions: don't
   start local read-ahead while Connecting (≤ 5 s); cancel the local `Now` job when the helper clip lands first; maybe
   2.5 s grace for the first item of a session. Once loaded, the engine stays until `EngineHost`'s 5-minute idle unload.
2. **Desktop (H3)**: preload the engine when a phone session opens, so the first urgent item isn't a cold load
   (harness: 0.9 s load + synth).
3. Model-missing text without the model's name and size (spec §3.11 "needs the Fast voice (111 MB)"): needs the
   bundle id from `Refused` in `HelperState`.
4. Not tested here (H5): real router/Wi-Fi off (adb runs over the same Wi-Fi), Doze `force-idle` with the screen off,
   `tcpdump` plaintext check, the user's Windows PC, 2× for 30 min, the 30-min battery comparison with the screen off.
5. Changing the system font size recreates the activity and lands on the library (navigation state isn't saved; seen
   before this milestone too).
