## API (spike subset of spec §5.2)

`LectriceCore::new(config, log)`, `engine_status`, `reload_engine`, `import_pdf`, `get_document`, `playback_order`,
`list_voices`, `speak_sentence`, plus `bench_synthesize(texts, voice) -> BenchResult` and `bench_speak(text, voice) -> WAV`
behind `bench`.

Differences from the spec, on purpose:
- No `CoreListener` / `AudioEncoderSink` in the constructor (the spike has no export); `NoExporter` refuses exports
  with `ExporterUnavailable`.
- `CoreConfig` has no `engine`: the engine loads only through `reload_engine` (spec §5.4 "lazy"). It has a `cache_dir`
  (core C29).
- `EngineConfig::Kokoro` has `variant` (C11). `EngineStatus::Ready` carries `load_ms`.
- **`CoreError::Failed.message` is `user_message`**: uniffi makes it a Kotlin exception, and a field named `message`
  clashes with `Throwable.message` (the Kotlin compile fails). The spec §5.2 needs this change.
- `SpokenAudio { wav, duration_ms, ready_ahead_ms }`: no `cache_hit` (the core doesn't report it).
- `reload_engine` drops the old engine before loading the new one (two models never in memory at once).
- `bench_speak` is new: the plan wants one WAV per provider to listen to.
- Bindgen is a separate crate, and the release profile keeps symbols (`strip = "debuginfo"`): uniffi-bindgen reads the
  API metadata from the symbol table, and with `strip = "symbols"` it finds none. AGP strips the libraries when it
  packages the APK (liblectrice_ffi.so: 5.7 MB built → 4.0 MB in the APK).
- The core dependency is `branch = "main"` until `v1.1.0` is tagged: Cargo fetches the git source even when a patch
  replaces it, and the tag doesn't exist yet.

once.

## Found on the way (for the core / later)

- **Core: `ImportPdf` logs `file_name` at info** (`import_pdf.rs:97`). A file name can be a book title; the spike passes
  a neutral `import.pdf`, but the real app will pass the user's name. Suggest logging only its length or nothing.
- **Core: no `core_version()` source.** The ffi can't read a core crate's version; a `pub const VERSION` in a core crate
  would do. The spike records `git describe --dirty` of the core checkout in `BuildConfig.CORE_REVISION` instead.
- **sherpa-onnx 2.0 logs every skipped (OOV) word** with the word itself (on Android through logcat). That is book text
  in the system log. The spike filters those lines out of its result file; the app should consider it before switching
  to 2.0 (no switch to turn it off in the Rust API).
- `liblectrice_ffi.so` holds about 170 absolute `/home/kia/...` paths (panic locations, registry paths). Harmless, but a
  public release build should add `--remap-path-prefix`.
- cargo-ndk `-o` also copied pdfium-render's own cdylib (`libpdfium_render-*.so`, 0.5 MB, never loaded); the script
  copies by name instead.
