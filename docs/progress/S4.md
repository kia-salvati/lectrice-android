## Build

```bash
cd ~/Desktop/learning/lectrice-android
./gradlew :spike:assembleSherpa1Release :spike:assembleSherpa2Release
```

Needs `local.properties` (gitignored) with `sdk.dir=…` and, on this network, `lectrice.googleMavenMirror=https://maven.aliyun.com/repository/google`.
Gradle runs `rust/build-android.sh` per flavor (tasks `buildRustSherpa1` / `buildRustSherpa2`), whose outputs are added
as generated jniLibs and Kotlin sources through the AGP variant API. Second build: 4 s with configuration cache.
Dependency verification is on (`gradle/verification-metadata.xml`, `verification-keyring.{gpg,keys}`).

## The app (`spike/`)

`minSdk 29`, arm64-v8a only, release with R8 (`proguard-rules.pro` keeps JNA and `uniffi.lectrice_ffi.**`), signed with
the debug key, flavors `sherpa1` / `sherpa2` (application id suffixes, side by side). One Compose screen: chips for
model (fp32/int8), threads (2/4/6/8), provider (cpu/xnnpack/nnapi), "bench 6 threads too" (on by default from API 36,
i.e. the S26 Ultra), the buttons and a text log. The screen stays on.

| Button | Does |
|---|---|
| 1 Import PDF | SAF picker → copy to `cacheDir/import/<uuid>.pdf` → `import_pdf` (as `import.pdf`) → `get_document`. Records copy, import and `get_document` times, pages, sentences, blocks, records, TOC entries |
| 2 Engine | `reload_engine` with the chips; records load time, `VmRSS`/`VmHWM`, and the sherpa log lines about providers (read back with `logcat -d --pid`, OOV lines left out) + whether a fallback was logged |
| 3 Bench | {fp32, int8} × {2, 4, 8 (+6)} on cpu, 3 runs each, first discarded; median RTF, every run's per-sentence numbers |
| 3b Accelerators | at each bundle's best thread count: cpu, xnnpack, nnapi, 3 runs each; engaged, RTF, max clip-duration deviation vs cpu (±3 %), one WAV per provider in `files/results/wav/` |
| 4 Soak 10 min | the chips' choice, bench text on a loop; every 10 s: RTF, thermal status + headroom, battery temp/%/charging, charge counter, current, VmRSS/VmHWM; mAh per audio minute. Refuses while charging |
| 5 Play 2 min | from the first top-level TOC entry: ExoPlayer playlist (80 items) of `lectrice://sentence/<doc>/<id>` through `SentenceDataSource` → `speak_sentence`; records time to first sound, rebuffers (count, time, item), transitions, and each `open`'s wait and `ready_ahead_ms` |
| 6 Run all | 2 → 3 → 3b → 4 at the overall best combination → 5-minute battery runs for providers that engaged, agreed and weren't slower. On `sherpa2`: fp32 and int8 at the chosen thread count only |
| 7 Share results | the JSON + WAVs through the share sheet (FileProvider) |

Result file: `files/results/<model>-<UTC timestamp>.json`, rewritten after each part. Device (manufacturer, model, board,
hardware, SoC, RAM, Android/API, page size, ABIs, CPUs), app version, sherpa set, core revision (`git describe --dirty`
of `../lectrice` or `../lectrice-sherpa2` at build time), pdfium binding (bare name or full path). Only ids, counts and
durations.

`spike/src/main/assets/bench-text.txt`: 20 invented sentences (a morning ferry trip, 259 words, about 1.3 min of audio).
Not from any book.

`spike/push-model.sh <serial> fp32|int8 [sherpa1|sherpa2]`: pushes only the files the English engine reads (the
sherpa2 set without `espeak-ng-data`) to `/data/local/tmp`, then into the app's external files folder
(`/sdcard/Android/data/<pkg>/files/models/`), which adb can write without `run-as` (UNVERIFIED on One UI); the app
moves it into `files/models/` on the next Engine press. Fallback: `run-as`, which needs a debuggable build. This differs
from the plan (`run-as` only), because a release build isn't debuggable.
