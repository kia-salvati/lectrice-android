## What was built

### Models (file 01, user decision 2026-10-25)

- `ModelCatalog` offers **Fast** (ours, q8, default and "Recommended", release `model-kokoro-lectrice-fast-v1`), **Full
  quality** (official fp32 from sherpa-onnx's `tts-models` release) and **Small** (ours, w8, `model-kokoro-lectrice-small-v1`),
  each with the archive's URL, size and SHA-256 and its **own engine id**, the same as the desktop's:
  `kokoro-v1.0-lectrice-fast-v1`, `kokoro-v1.0`, `kokoro-v1.0-lectrice-small-v1`. Installed sizes (English files only):
  169 MB, 384 MB, 169 MB; downloads 140 MB, 350 MB, 140 MB.
- `ModelInstaller`: one `.tar.bz2` per model (the published form) instead of the single files the spec planned; resumable
  `Range` downloads with `HttpURLConnection` (no OkHttp), space check (left to download + unpacked size + 200 MB), waits
  for a network (or Wi-Fi only), back-off 30 s → 5 min, 3 retries of a 5xx, SHA-256 of the whole archive checked
  (a mismatch retries once), then unpacked **by the core** (`unpack_model_archive`: `tar` + pure-Rust `bzip2`, only the
  kept files, links and `..` paths refused) into a staging folder renamed into place; an `.installed` marker is written
  last. "Import from a file…" takes the same `.tar.bz2` and identifies it by its SHA-256.
- `AndroidVoiceModels` (`VoiceModelRepository`): statuses, download/pause/cancel, use, delete (not the one in use),
  import, metered check, measured RTF per model (falls back to the spike's numbers per phone class).
- `ModelSetupViewModel` (S1–S4, T2) and the screens (Fable).

### Export (file 10)

- Rust: `AndroidExporter` (`lectrice-ffi`) implements the core's `AudioExporter`: each part is encoded **to AAC as it is
  made** (so parts take the final file's space, matching file 10 §3.11), assembled into an M4B by Kotlin. Exposed through
  a Kotlin callback (`AudioEncoderSink`) set at start (`set_encoder_sink`). Speed baked in by the core's Sonic stretch
  (`time-stretch` feature now on). FFI: `start_export`, `estimate_export`, `list_all_exports`, `pause_export`,
  `pause_all_exports`, `resume_exports`, `resume_export`, `cancel_export`, `delete_export`, `mark_export_saved`.
- Kotlin `AacEncoderSink` (`core:work`): MediaCodec AAC-LC mono 64 kbit/s → ADTS part files; `assemble` remuxes the parts
  with MediaExtractor → MediaMuxer (the encoder's priming frame is dropped between parts so chapter times don't drift),
  then `Mp4Tags` (pure JVM, tested) appends a new `moov` with `udta/chpl` chapter marks and `©nam/©ART/©alb/©gen` tags
  and turns the old `moov` into `free` (no `stco` offsets change).
- `CoreExportRepository`: the records, estimate, start/pause/resume/cancel/delete, **Save to Audiobooks = move** (MediaStore
  `Audiobooks/Lectrice/`, pending → copy → published, then the private file deleted and `mark_export_saved`), free space.
- `ExportViewModel` (feature:reader): E1 choices (voice, the three models with download, speed, read code), the footer
  estimate (length, size, make time from the measured RTF), E6 not enough space with "Export part of the book", E7 range of
  chapter-level entries (or page steps without a TOC) with the suggested range that fits, E2/E3/E5/E5b/failed states with
  their causes, E4 done (Save to Audiobooks, Save as…, Share, Make another version), cancel confirm. `ExportSpace` (pure,
  JVM-tested) holds the formulas.
- `BackgroundWorkService` (foreground, `mediaProcessing` on API 35+, `dataSync` for downloads/below): watches the core's
  export runner, holds the engine, **loads the export's model when nobody listens** (file 10 §3.6), pauses exports at
  thermal CRITICAL / battery saver / ≤ 15 % not charging, handles Android 15's time limit (`onTimeout` → paused "System",
  continued when the app comes to the front), notification with Pause/Cancel and a result notification. No WorkManager
  (plan §5).

### Prepare (file 14; core C21)

- Core (main repo worktree): `PrepareJobs` in `SpeechServices.prepare` makes a sentence range into the audio cache at
  export priority, skipping cached clips, and pins the range (`AudioRetention::pin`; `FsAudioCache` keeps pinned clips out
  of the 60-minute window). Tests in `lectrice-app` (`prepare.rs`) and `lectrice-infra` (`storage_audio_cache.rs`).
- FFI `start_prepare`, `stop_prepare`, `cancel_prepare`, `prepare_status`.
- `PrepareCenter` (`core:work`): requests kept in preferences, run by the work service **only while charging and above
  15 %**, stopped when unplugged, dropped after 14 days. A charger broadcast starts the service while the app process
  lives. Reader: "Prepare while charging" (This chapter · Next 3 chapters · As much as fits, the last capped at the cache
  cap − 100 MB) shown only on slow phones (`VoiceModelRepository.isSlowPhone`).

## Checked on the Galaxy S26 Ultra (2026-10-26, locked phone, debug hook `--es lectrice.export <docId> --ei lectrice.speed 150`)

- A whole invented 17-page book (709 sentences, 30 TOC entries) exported with Fast at **1.5×**: 6 AAC parts, assembled into
  a 17.6 MB M4B. `ffprobe`: AAC-LC 24 kHz mono 64 kbit/s, duration **2146.9 s vs 2146.5 s expected** (1× audio 3219.8 s ÷ 1.5,
  +0.02 %), **30 chapters read from `chpl`** with their titles, tags title / artist / album / genre "Audiobook".
- Killing the app mid-export and opening it again: the export continued from the next part (4 of 6 parts kept).
- **Bug found and fixed:** the work service crashed at start ("Starting FGS with type none"): `ServiceCompat.startForeground`
  masks out `mediaProcessing` on the API 34 path; now `Service.startForeground` is called directly.
- **Bug found and fixed:** `start_export`/`estimate_export` failed with `SpeechEngineUnavailable` when no book had been
  played (the core's export services exist only with a loaded engine); the repository now loads the engine first, off the
  main thread (`EngineHost.ensureLoaded` switches to IO).
- Cost: the export ran at ~212 % CPU on 8 threads; the unplugged phone went from 24 % to 16 % battery and reached 42.8 °C
  in ~26 minutes (stopped and finished on the charger). This supports pausing exports when hot (thermal CRITICAL) and
  suggests a lower export thread count is worth measuring.
- Not seen: the notification itself (the phone stayed locked), Save to Audiobooks, Share, the export page UI.
